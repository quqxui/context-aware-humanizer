# 中文工作消息

用于工作聊天、邮件、进度同步、任务交接、催办和升级反馈。让读者迅速找到主题、动作、负责人、时间和阻塞项。

## 使用实例

以下均为自拟示例，只演示改写方式，不是模型评测结果。

### 示例一：同步部署并交接回归

**需求：** 改成简洁的工作同步，保留负责人、截止时间和环境范围。

**原文：** 支付接口超时问题的修复已经完成预发部署。请 Qiao 在明日 16:00 前完成回归检查，生产环境暂不变更。

**改写：** 支付接口超时修复已部署到预发。请 Qiao 于明日 16:00 前完成回归；生产环境暂不变更。

**为什么：** 删掉冗余表达，保留预发状态、回归负责人、截止时间和生产环境暂不变更的范围。

### 示例二：说清当前阻塞项

**需求：** 整理进展和依赖，不添加截止时间或新的承诺。

**原文：** 设计评审昨天已经上传了，不过目前移动端还没有对 API 字段完成确认。我需要等到确认之后，才能进行 integration 分支的更新。

**改写：** 设计评审昨天已上传。移动端还没确认 API 字段，我需要等确认后再更新 integration 分支。

**为什么：** 分开已完成事项与待确认事项，保留更新分支的前提，没有擅自给移动端加负责人、时间或升级安排。

## 按消息目的组织

| 消息类型 | 优先说明 |
|---|---|
| 进度同步 | 当前状态、已有依据和影响 |
| 提出请求 | 请谁做什么，以及必要背景 |
| 跟进事项 | 前一项工作、当前阻塞和需要的答复 |
| 升级反馈 | 已知影响、已尝试的处理和需要的决定 |

只使用原文已有信息；不为填满表格而补写缺失内容。

## 中文工作消息的写法

- 主题和动作尽量靠前。只有一项确认时，可以只写一句；多个独立交接项才适合列点。
- 把“对结果进行分析”“完成对配置的修改”等表达改成直接动词，同时保留范围和方法。
- 已完成、待处理、拟开展分别写清。“已部署到预发”不能缩成没有环境限定的“已上线”。
- 保留姓名、日期、时间、分支、命令和依赖关系，不把相对时间自行换算成具体日期。
- 保留“预计”“尽量”“如果”“前”“后”等承诺和时间限制；“请完成”不能随意改成“有空看看”。
- 沿用原文简繁体、地区用语和称呼。省略主语时，负责人仍须明确。
- 不自动补“辛苦啦”“感谢支持”“有问题随时联系”，也不增加催促或指责。

## 交付方式

默认只给可发送的消息。保留原文适用的段落、列表或邮件格式，不把一条消息扩成周报。已经清楚且符合语气要求时可以不改。
