# 中文说明文档

用于 README、安装说明、API 和命令行文档、内部流程、故障处理文档和技术解释。围绕读者要完成的任务改写，保留执行所需的技术细节。

## 使用实例

以下均为自拟示例，只演示改写方式，不是模型评测结果；命令也只是示例文本，不需要执行。

### 示例一：精简快速开始

**需求：** 保留命令、输入文件、成功条件和输出路径，去掉生硬表达。

**原文：** 通过执行 `sampletool run --config demo.yaml` 命令，可以实现对 `demo.yaml` 的读取，并在执行成功后将结果写入 `out/result.json`。

**改写：** 运行 `sampletool run --config demo.yaml`。命令读取 `demo.yaml`，成功后将结果写入 `out/result.json`。

**为什么：** 精简命令周围的说明，命令、文件路径和成功后的行为都保持不变。

### 示例二：不猜配置值的排查条目

**需求：** 改成便于查阅的错误排查条目，不补资料缺失的值。

**原文：** 如果运行 `sampletool run --config demo.yaml` 时出现 `ConfigError: missing key: output`，请检查 `demo.yaml` 是否包含 `output` 键。当前资料没有给出该键应使用的值。

**改写：**

> 运行 `sampletool run --config demo.yaml` 时若出现 `ConfigError: missing key: output`：
>
> - 检查 `demo.yaml` 是否包含 `output` 键。
> - 资料未提供该键的取值。

**为什么：** 排查条件、检查动作和信息缺口分开呈现。没有猜一个配置值，也没有声称检查后故障就能解决。

## 按读者任务组织

| 文档类型 | 优先说明 |
|---|---|
| 快速开始 | 已知前提、最少步骤和预期结果 |
| 参数参考 | 精确参数、返回值、限制和已有示例 |
| 故障处理 | 排查条件、命令、判断点和已有恢复步骤 |
| 概念解释 | 与实际任务有关的定义、输入、输出和职责 |

只写材料支持的项目；缺失的依赖、兼容范围或恢复方法不能自行补齐。

## 中文文档的写法

- 先确认目标读者及任务。已有专业术语有明确含义时保留，不用泛化短句替代。
- 用直接动词减少“进行读取”“执行停机操作”一类冗余，但保留主体、周期、阈值和触发条件。
- 命令、参数、路径、标识符、版本和输出文本保持原样。只改周围说明，除非用户明确要求改动这些内容。
- 区分前提、动作、成功结果和失败条件；“成功后写入”不能缩成无条件“写入”。
- 占位符和环境相关值要沿用材料中的标记，不能把示例值写成适用于所有环境的值。
- 保留简繁体和地区用语；省略主语时，仍应清楚是哪条命令或哪个组件执行动作。
- 操作步骤可用编号，多个参数可用表格，完整命令可用代码块。小范围润色不必重排全文。
- 不添加未经提供的成功结果、安装依赖、版本兼容性或故障恢复命令。

## 交付方式

默认输出修改后的文档片段，保留有效格式和必要术语。已经准确、清楚且能支持读者任务时可以不改。
